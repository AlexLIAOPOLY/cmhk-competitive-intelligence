# 个人新闻简介与三天去重

2026-09-12：实际发送卡片中存在标题级摘要原样改写，旧编辑器只校验长度、格式和编辑提醒，没有检查简介的信息增量。截图所示合作新闻的原始摘录本身也只有标题内容。

- 编辑器 v9 增加高重复检查和独立模型事实审核。简介必须补充标题之外的具体事实，保存简介细节及来源逐字引文；不足则重新编辑，失败留在原批次重试，不能用旧简介或规则文本兜底。
- 准备阶段为稀薄摘录读取同一新闻原文正文，过滤广告、菜单及推荐阅读；原文 URL、网页标题与正文一并参与证据和缓存身份。正文所属事件也要复核，不能把跳转后的另一篇报道当来源。
- 最近三个香港自然日（含当天）的个人回执统一覆盖自动、人工、早晚、跨天和重试。恢复历史素材审计中按 news_id 关联的原文地址，聚合和解析后原文共用身份；先合并所有别名，再选稿，避免较晚出现的别名绕过历史。
- 原文解析后再做一次精确去重。提前准备后若个人历史、编辑器、技能或去重版本变化，发送前要求重新准备；发送结果不明或已有消息回执则继续恢复原请求。
- 已同步项目技能及本机安装技能。没有修改、重发任何历史消息。

真实调用还发现：逐条恢复时网关有时返回完整的单条 `items` 外壳，与请求的单对象结构不同。现仅对完整 JSON、唯一条目、正确 ID 和齐全字段兼容解包，再执行同样的简介及事实审核；截断、字符串数组和错误编号仍拒绝，不改写或补造模型正文。

验证：213 项隔离专项回归通过；生产新闻池 9,095 条在 14 位启用订阅者的真实三天历史上只读选稿回放，ID、标题及 URL 身份重复均为零。该回放未调用模型，不等同于完整语义审核或实际发送。

证据保存在私有运行目录 `var/subscriptions/title-summary-20260912/`：`tests.log`、`history-replay.json`、真实模型仅准备验证的 `live-results.json`。真实模型调用、运行激活和仓库同步分别核验，不能把失败的模型响应记为准备成功。
