# 飞书个人偏好对话

用户可私聊新闻推送机器人，例如“我想多接收AI相关的新闻”“都行，你定”“更关注AI在医疗中的应用”“我希望多收一些国际新闻”“每天一次，每次5条，上午八点半收”。后台调用内部大模型生成字段提案，校验后保存，回复本次变化及当前设置。

每次成功后回复“已成功更新你的喜好”及完整的1、2、3编号清单。用户回复“行/确认”时，记录本人确认的版本；继续提出修改时，保存并回复新版清单，后续推送读取最新生效设置。后台保留各次原话、变化和确认记录；管理员在用户阅读后改过设置时，先展示新清单，不能把旧的确认套到未见过的新设置上。

## 自由主题与自动安排

- `news_topics` 按用户持久保存主题名称和同义/相关词，不以七个栏目作为主题选项。例如人工智能、量子通信，或AI医疗应用等细分兴趣。复合主题支持“AI&医疗”这样的共同条件，避免把所有AI新闻误当成医疗AI。
- “你定/都行/随机安排”承接本人的近24小时、最多6轮对话及当前主题，模型围绕已表达的兴趣选择2—3个关注方向；只在这次授权时安排，保存后查看、确认、重启和推送不再随机。未表达主题时先问感兴趣的内容，不随机改动收件时间、总条数或无关喜好。
- “再加上”“刚才第三个”“换成”等短句可引用本人已保存的主题名称。话题新增、细化、移除和清空均保留审计；编号清单逐项列出每个主题。
- 自动、手动、原轮次替换选稿均读取当前用户的主题。主题可以跨原栏目增加相关候选，不把所在栏目的其他不相关新闻一并加入；仍保留每次最多4个栏目、地域偏好、新鲜度、事实/图片审核及个人历史去重。
- 主题改变纳入个人准备校验，尚未发送的旧准备结果失效；已经发送或结果不明的原请求保留，不能因偏好改变重发。旧设置卡或后台表单未提供主题时保留本人主题，恢复默认时按对应快照恢复。

## 飞书配置

在对应应用的“事件与回调”中选择长连接，订阅 `im.message.receive_v1`，开通 `im:message.p2p_msg:readonly`（读取用户发给机器人的单聊消息）及发送消息权限，并创建版本发布。`im:message` 或已有群消息权限不能替代单聊事件读取权限。需企业审核的权限必须审核通过后才会生效；仅保存开发配置或仅发布事件订阅不够。

现有 `project_monitor_card_actions.py` 常驻进程通过同一个 lark-cli 事件总线同时消费卡片回调及个人消息。接收阶段只写入持久队列；模型与回复在后台线程执行，不阻塞卡片回调。

官方说明：[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)。

## 保存和用户隔离

- 只接收指定推送应用下真实用户的单聊；群消息、机器人消息、其他应用的消息不进入偏好解析。
- 使用事件发送者的应用内用户标识定位原订阅。模型无法指定收件人、SQL、服务或账户状态。
- 可以保存自由关注主题，以及地域优先、兴趣板块、频率、条数、时间和报告形式。没有提及的字段保留；有歧义或不支持的要求整条不保存。
- 模型提取修改操作，只接收本人的近期对话和已保存主题名称来理解指代，不接收用户身份、其他人的记录或已保存的时间等设置。将本次要求、本人已存主题、本人近期对话和此次安排角度作为完整的 `request_context` 对象，返回时逐项核对；不能只核对“你定”这类短回复或独立的随机请求编号。旧版或不一致的响应拒绝写入，并保存诊断分类。数字与接收时间还需通过原话校验。失败时保留旧设置并回复。未提及的时间段由后台按本人原设置补齐，避免模型或上游相似回答携带其他人的旧设置。
- SQLite 事务同时保存偏好、修改清单、原话及待发回复。提交前核对当前设置，避免覆盖管理员或卡片刚提交的变更。
- 同一应用的消息 ID 唯一去重；每位用户的待处理消息按顺序处理，延迟旧消息不得覆盖新的修改。
- 已保存但未回复的记录可在重启后恢复。回复使用稳定幂等键，已取得消息 ID 后只重试回读；超出幂等窗口的未知发送进入待核实状态。
- 自动和手动新闻推送沿用原订阅表及按人读取的准备校验，偏好变更使该人的旧准备结果失效。图片、摘要、历史去重规则继续使用既有链路。

后台“订阅者”姓名下的“偏好与对话”可查看编号清单、原话、本次保存变化和回复状态；以已保存值为准，支持桌面及手机抽屉阅读。
