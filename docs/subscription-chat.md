# 飞书个人偏好对话

用户可私聊新闻推送机器人，也可在群聊中使用飞书真正的 @ 选择“科创及数智化”后发送要求，例如“我想多接收AI相关的新闻”“都行，你定”“更关注AI在医疗中的应用”“我希望多收一些国际新闻”“每天一次，每次5条，上午八点半收”。后台调用内部大模型生成字段提案，校验后保存，回复本次变化及当前设置。

同一个入口也支持订阅名单自助管理。真实发言者发送“加入订阅名单”时，首次按默认战略新闻设置开启；已有记录的人恢复上次选择的订阅内容和偏好。发送“退出订阅名单”时停止本人全部后续推送，但保留原设置以便恢复。两种动作都只使用事件中的真实发言者身份，不允许替他人操作。

每次成功后回复“已成功更新你的喜好”及完整的1、2、3编号清单。用户回复“行/确认”时，记录本人确认的版本；继续提出修改时，保存并回复新版清单，后续推送读取最新生效设置。后台保留各次原话、变化和确认记录；管理员在用户阅读后改过设置时，先展示新清单，不能把旧的确认套到未见过的新设置上。

## 每位读者的个人阅读说明

- `news_personal_skill` 是每位读者持久保存的自由文字需求列表，不设主题或分类枚举。模型理解用户意图后新增、细化、纠正或删除相应条目，保留其他需求。例如“喜欢生活类内容”“不要明星八卦”“想了解原理”“多给我一些周末用得上的信息”。
- “你定”根据本人的兴趣和近期对话自主选择关注方向，不从预设方向表抽取；安排后保存，查看、确认、重启和推送均不重新随机。旧 `news_topics` 仅作兼容，升级时将已有主题原意转换为个人说明。
- 说明保存在本人数据库记录，同时导出 `var/subscriptions/personal-news-skills/<应用及用户散列>/SKILL.md`；版本由说明内容计算。后台编号显示当前说明、历史原话、每次修改、本人确认及上次智能选稿的理由。
- 分配信息的模型在**准备阶段**读取本人说明，对原审核批次中当天/昨天且未发过的文章逐篇作语义判断；标题不必含“生活”之类的字面关键词。明确排除的内容不选，其余按相关程度、地域偏好排序。个人说明生效时，旧栏目列表和最多四栏限制不再作为选稿准入规则。
- 自动入队和手动选择只提供初始候选，准备时从原批次恢复完整候选池，再调用个人选稿Agent。模型每批判断24条并保存检查点；失败重试复用已完成判断。缓存按应用、用户、说明版本、模型及文章证据隔离，其他人的说明、缓存和选稿不能混用。发送线程仍只读取已准备结果，不临时调用模型。
- 模型输出须回显完整阅读要求，逐条返回由文章证据生成的候选标识、判断、相关程度和理由；缺项、越界或会话不一致不能进入图文准备。说明在模型工作期间发生改变时，旧准备作废，读取本人新说明重做。
- 文章仍须通过原文事实、摘要、图片和个人历史去重审核。个人阅读要求用于挑选现有原审核池内的内容；不会凭空生成新闻或将另一轮未审核资料混入。如果池中缺少符合需求的文章，保存缺额，不编造内容。
- 旧设置卡或后台表单未提交个人说明时，保留原说明；恢复默认按快照恢复。没有个人阅读说明的用户继续沿用原订阅行为。

## 飞书配置

在对应应用的“事件与回调”中选择长连接，订阅 `im.message.receive_v1`，开通 `im:message.p2p_msg:readonly`（读取用户发给机器人的单聊消息）及发送消息权限；群聊另需 `im:message.group_at_msg:readonly` 或已开通的 `im:message.group_at_msg.include_bot:readonly`，并创建版本发布。`im:message` 或已有群消息权限不能替代单聊事件读取权限。需企业审核的权限必须审核通过后才会生效；仅保存开发配置或仅发布事件订阅不够。

现有 `project_monitor_card_actions.py` 常驻进程通过同一个 lark-cli 事件总线同时消费卡片回调及个人消息。接收阶段只写入持久队列；模型与回复在后台线程执行，不阻塞卡片回调。

官方说明：[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)。

## 保存和用户隔离

- 只接收指定推送应用下真实用户的单聊，或明确 @ 本机器人的群消息。使用可信事件的 mentions.id 与配置 delivery_bot_open_id 核对；只输入同名文字、@ 其他人/机器人以及机器人发送的消息不触发。只移除本机器人的 @ 标记，用户需求交给同一模型处理。
- 使用事件发送者的应用内用户标识定位原订阅。模型无法指定收件人、SQL、服务或账户状态。
- 加入、恢复、退出和重复请求都由确定性指令解析处理，不将身份或名单权限交给模型。退出会把本人标记为 `unsubscribed` 并关闭全部服务；恢复时优先取本人 `default_preferences.services`，无历史选择才默认订阅“战略新闻”。
- 群聊仍以实际发言者定位本人资料及近期对话，群内其他人的内容不能混入；同一人的群聊与私聊沿用同一已保存说明。群回复挂在原消息下，并使用原消息对应的稳定幂等键；重启、重试、重复事件不能重新修改或额外私聊发送。每次群沟通（包括“你定”“行”）请 @ 本机器人。
- 首次选择、修改表单、保存回执和每日新闻卡片底部均提示可以直接回复喜好；表单另提示群聊 @ 的入口。
- 可以保存自由关注主题，以及地域优先、兴趣板块、频率、条数、时间和报告形式。没有提及的字段保留；有歧义或不支持的要求整条不保存。
- 模型提取修改操作，只接收本人的近期对话和已保存主题名称来理解指代，不接收用户身份、其他人的记录或已保存的时间等设置。将本次要求、本人已存主题、本人阅读说明、本人近期对话和自主安排标记作为完整的 `request_context` 对象，返回时逐项核对；不能只核对“你定”这类短回复或独立的随机请求编号。旧版或不一致的响应拒绝写入，并保存诊断分类。数字与接收时间还需通过原话校验。失败时保留旧设置并回复。未提及的时间段由后台按本人原设置补齐，避免模型或上游相似回答携带其他人的旧设置。
- SQLite 事务同时保存偏好、修改清单、原话及待发回复。提交前核对当前设置，避免覆盖管理员或卡片刚提交的变更。
- 同一应用的消息 ID 唯一去重；每位用户的待处理消息按顺序处理，延迟旧消息不得覆盖新的修改。
- 已保存但未回复的记录可在重启后恢复。回复使用稳定幂等键，已取得消息 ID 后只重试回读；超出幂等窗口的未知发送进入待核实状态。
- 自动和手动新闻推送沿用原订阅表及按人读取的准备校验，偏好变更使该人的旧准备结果失效。图片、摘要、历史去重规则继续使用既有链路。

后台“订阅者”姓名下的“偏好与对话”可查看编号清单、原话、本次保存变化和回复状态；以已保存值为准，支持桌面及手机抽屉阅读。
