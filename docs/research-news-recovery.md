# Research and news recovery

2026-09-11

News acceptance review keeps the initial candidate decisions and a durable, unpublished repair draft. A validation error selects the implicated event groups for repair. Other groups remain unchanged. A complete result must still pass the original evidence, field, partition and duplicate checks before any review cell is written. Distinct products, contracts and investment announcements at one conference are separate events.

One input permits at most 12 repair requests and 3 requests for any one scope or candidate, including requests interrupted by a process or network failure. Protocol 5 collects all invalid groups and sends their actual draft and individual errors together. Exhaustion raises `NewsSelectionQualityBlocked`. The scan archive, parent task and generic queue receive the same terminal state and an empty next retry time. Recovery never replays the scan or its notifications. A failed completion receipt retries only the receipt, without another model call.

Four-library recovery uses the original research run and task. Temporary metric failures, including incomplete model/tool output, reopen only those metrics. Existing accepted facts survive the merge and pass formal-table preflight again. Unit handling accepts explicit native currency, scale, count and fiscal-period notation; ambiguous currency and non-exact amounts remain rejected. ARPU values are bound to their specific business label, organic revenue retains its definition, and a total customer chart cannot supply a postpaid count. Candidate recovery and formal replay share all three writer locks continuously.

The daily dispatcher records up to 6 delayed recoveries, honors user cancellation and detects a dead worker. Successful publication is not whole-run completion while retryable metrics remain. Temporary model failures can use explicitly configured DeepSeek routes; shared key cooldown and the global rate limiter still apply. Macro indicators refresh independently in incremental research, once per run while the saved database hash matches. AI checkpoints are tied to exact evidence and the analysis protocol and are validated before reuse; they never substitute rule-generated text for AI.

Use the existing queued Web reload to load source changes. Verify activation, runtime hashes and resident monitors before recovery. The existing `data_curation.repair_research_storage` CLI provides a read-only preview and a backed-up application of archived facts. The daily worker CLI resumes the same run. Do not clear successful decisions, reset retry counters, relax evidence checks or replay group notifications to recover a failed batch.

Focused regression coverage includes process interruption, publication-only resume, model tool argument preservation, cache invalidation, partial news repair, terminal-state reconciliation, unit and period boundaries, and the rendered recovery state.
