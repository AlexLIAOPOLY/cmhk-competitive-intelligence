# 四库与 AI 分析自动发布状态

本目录由 `executive_intelligence_pipeline.py` 管理。

- `ai_analysis.json`：最近一次通过 Agent 发布门禁的四域分析事实。
- `latest.json`：四库重建、校验、原子发布和失败回退状态。
- `refresh.log`：后台刷新日志。
- `curation-<run_id>.json`：触发本轮刷新所用的 Agent 摘要。
- 各四库目录的 `agent_verified_facts.json`：本轮 accepted、证据完整且来源层级为
  `official` 的旁路事实；新财报事实可先进入穿透分析，但不会绕过主表口径门禁覆盖 KPI。

这些 JSON 和日志属于运行态，不提交到公开开发分支。每日定时爬虫完成完整 Agent 审核后，
由 `scheduler.py` 异步启动发布桥；发布桥失败不会改变原爬虫和飞书同步的成功状态。
数据库候选必须通过行数不降级、期间不倒退、来源与验证状态门禁，才会原子替换正式目录。
前端取数如同时存在标准化值与 `official_value`，一律优先展示官方值；标准化值只保留作
差异审计。主表未能确认期间、单位或可比口径时，继续保留旧值和披露缺口，不让 AI 猜数。

页面中的四域总览、16 个分类视图和跨库发现统一消费 `ai_analysis.json` 的模型分析产物。
发布桥对全部输入证据计算统一指纹；任一指标、期间、口径或来源发生变化时，旧总结不会局部复用，
而是整批重新生成并再次通过数字、来源和分类覆盖门禁。模型不可用或输出未过门禁时，只发布由
同一批已核验证据生成的保守回退总结，避免前端保留与新数据不一致的旧文案。
